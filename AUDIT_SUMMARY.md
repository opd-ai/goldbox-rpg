# WASM Client / JSON-RPC Server Bug Audit Summary

**Date**: 2026-03-17
**Scope**: `pkg/wasmui/`, `cmd/wasm-ui/`, `pkg/server/`, `web/static/assets/`

## Bugs Found and Fixed

### 1. CreateCharacter RPC parameter mismatch (CRITICAL)

- **File**: `pkg/wasmui/rpc_methods.go:63`
- **Bug**: Client sent `"method"` as the attribute generation parameter key, but the server handler (`pkg/server/handlers.go` `createCharacterRequest` struct) expects `"attribute_method"`.
- **Impact**: Character creation always failed — the server ignored the attribute method, defaulting silently or returning an error.
- **Fix**: Changed param key from `"method"` to `"attribute_method"`.

### 2. `errorf` helper ignores format arguments (MEDIUM)

- **File**: `pkg/wasmui/adventure_screen.go:388`
- **Bug**: The `errorf(format string, args ...interface{})` function returned the raw format string without applying `fmt.Sprintf`, so any future callers passing format arguments would get an unformatted message.
- **Impact**: Currently benign (no callers pass format args), but a latent bug that would produce incorrect error messages if the function were used with arguments.
- **Fix**: Changed body to `fmt.Sprintf(format, args...)`.

### 3. UnequipItem called with item ID instead of slot name (CRITICAL)

- **File**: `pkg/wasmui/overlays.go:82`
- **Bug**: `g.rpcClient.UnequipItem(item.ID)` passed the item's unique ID where the server handler (`handleUnequipItem`) expects a slot name (e.g., `"head"`, `"chest"`, `"weaponmain"`).
- **Impact**: Unequip always failed because `item.ID` (a UUID) could never parse as a valid equipment slot name.
- **Fix**: Changed to `g.rpcClient.UnequipItem(item.Slot)`.

### 4. Nil pointer dereference in `getSessionForMove` (HIGH)

- **File**: `pkg/server/handlers.go:143`
- **Bug**: `getSessionForMove` retrieved a session via `getSessionSafely()` which validates session existence but does NOT check if `session.Player` is nil. Subsequent code in `handleMove` dereferences `session.Player` directly (e.g., `s.validateCombatConstraints(session.Player)`).
- **Impact**: Server panic (nil pointer dereference) if a session exists without an attached player (e.g., during the window between `joinGame` and `createCharacter`).
- **Fix**: Added `session.Player == nil` guard returning an error.

### 5. Nil pointer dereference in `validateAttackSession` (HIGH)

- **File**: `pkg/server/handlers.go:335`
- **Bug**: Same pattern as #4 — no nil check for `session.Player` after session retrieval.
- **Impact**: Server panic on attack attempt from a session without a player.
- **Fix**: Added `session.Player == nil` guard returning an error.

### 6. Nil pointer dereference in `validateSpellCastSession` (HIGH)

- **File**: `pkg/server/handlers.go:506`
- **Bug**: Same pattern — `session.Player` accessed without nil check.
- **Impact**: Server panic on spell cast from a playerless session.
- **Fix**: Added `session.Player == nil` guard returning an error.

### 7. Nil pointer dereference in `validateEndTurnSession` (HIGH)

- **File**: `pkg/server/handlers.go:863`
- **Bug**: Same pattern — `session.Player` accessed without nil check.
- **Impact**: Server panic on end-turn from a playerless session.
- **Fix**: Added `session.Player == nil` guard returning an error.

### 8. Nil pointer dereference in `handleApplyEffect` (HIGH)

- **File**: `pkg/server/handlers.go:1186`
- **Bug**: After retrieving a session with `getSession()`, the handler immediately calls `session.Player.GetID()` without checking if `Player` is nil.
- **Impact**: Server panic when applying effects from a session without a player.
- **Fix**: Added `session.Player == nil` guard returning an error.
